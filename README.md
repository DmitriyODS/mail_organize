# Локальный архив почты (IMAP)

`mail_archive.py` скачивает все письма из почтового ящика на компьютер и собирает из них архив, который открывается в браузере: список папок, список писем, сами письма и их вложения.

Что умеет скрипт:

| Команда | Что делает | Нужна сеть |
|---|---|---|
| `download` (по умолчанию) | скачивает письма с сервера | да |
| `render` | превращает готовую копию в HTML-страницы с вложениями | нет |
| `pack` | сильно сжимает архив в один файл `.tar.xz` | нет |
| `unpack` | разворачивает `.tar.xz` обратно в каталог | нет |
| `delete` | удаляет с сервера письма, у которых есть локальная копия | да |

Все команды, кроме `delete`, ящик **только читают**: на сервере ничего не удаляется, не перемещается и не помечается прочитанным.

## Что нужно

- Python 3.9 или новее (`python3 --version`). Сторонние библиотеки не нужны.
- Включённый доступ по IMAP к ящику, логин и пароль.
- Свободное место на диске: объём ящика плюс примерно столько же на HTML-страницы и вложения. Для ящика на 10 ГБ рассчитывайте на 20–25 ГБ.

## Быстрый старт

```bash
cd /Users/dmitriy/projects/mail_archive
python3 mail_archive.py
```

Дальше скрипт всё спросит сам. Когда закончит, откройте архив:

```bash
open archive/index.html
```

## Что происходит при запуске

### 1. Подключение

Скрипт спрашивает:

- **IMAP-сервер** — по умолчанию `mail.bmstu.ru` (просто Enter);
- **логин** — обычно полный адрес почты;
- **пароль** — при вводе не отображается и нигде не сохраняется.

Сервер, порт и логин после первого успешного входа запоминаются в `archive/config.json`, при следующих запусках спрашивается только пароль.

По умолчанию используется SSL на порту 993. Если сервер работает через STARTTLS на порту 143:

```bash
python3 mail_archive.py --starttls --port 143
```

### 2. Сканирование папок

Скрипт обходит все папки ящика и показывает таблицу:

```
  №    писем      размер  осталось    докачать  папка
  1     8421      6.2 ГБ      8421      6.2 ГБ  INBOX
  2     1310      2.9 ГБ      1310      2.9 ГБ  Отправленные
  3       57     12.4 МБ        57     12.4 МБ  Спам
```

- «писем» и «размер» — сколько лежит на сервере;
- «осталось» и «докачать» — сколько ещё не скачано локально.

На больших папках сканирование может занять до нескольких минут.

### 3. Выбор папок

```
Какие папки качать? [Enter — все, либо номера: 1,3-5]
```

- Enter — скачать все папки;
- `1,2` — только первую и вторую;
- `1,3-5` — первую и с третьей по пятую.

Так можно, например, не качать спам и корзину.

### 4. Скачивание

Скрипт показывает, сколько писем и какой объём предстоит скачать, сколько свободного места на диске, и спрашивает подтверждение. Затем появляется строка прогресса:

```
[#########...............]  38.2%  3710/9731  3.5 ГБ/9.1 ГБ  2.4 МБ/с  осталось 00:39:10  INBOX
```

Слева направо: доля скачанного, число писем, объём, текущая скорость, оценка оставшегося времени, текущая папка.

### 5. Сверка

В конце выводится итоговая таблица:

```
на сервере  локально  папка
      8421      8421  ✓ INBOX
      1310      1309  ✗ Отправленные
```

✓ означает, что все письма папки сохранены локально. ✗ — каких-то писем не хватает; запустите скрипт ещё раз.

### 6. Сборка HTML

Если скачивание дошло до конца, скрипт предложит собрать HTML-страницы. Это отдельный этап, он работает без сети — только с уже скачанными файлами. У него такая же строка прогресса, пауза и остановка.

## Управление во время работы

| Клавиша | Действие |
|---|---|
| `p` или пробел | пауза; повторное нажатие — продолжить |
| `q` | остановить |
| Ctrl+C | остановить; второй Ctrl+C — прервать немедленно |

- Enter нажимать не нужно. Клавиши работают и в русской раскладке (`з` и `й`).
- Пауза и остановка срабатывают **после текущего письма**. Если сейчас качается письмо с большим вложением, реакция будет через несколько секунд.
- Во время паузы скрипт раз в минуту «пингует» сервер, чтобы соединение не закрылось. Если оно всё же оборвётся, после снятия паузы скрипт переподключится сам.
- После остановки ничего не теряется: следующий запуск продолжит с того же места.

## Повторные запуски и докачка

Скрипт можно запускать сколько угодно раз:

- уже скачанные письма не перекачиваются;
- новые письма, пришедшие с прошлого запуска, докачиваются;
- письма, удалённые с сервера, **остаются** в локальном архиве — локально скрипт ничего не удаляет.

При обрыве связи скрипт сам переподключается, до 5 попыток на письмо с растущей паузой. Если три письма подряд скачать не удалось, он считает, что связи нет, и останавливается — просто запустите его позже.

## Команды и параметры

```bash
python3 mail_archive.py              # скачать письма, затем предложить сборку HTML
python3 mail_archive.py download     # то же самое
python3 mail_archive.py render       # превратить готовую копию в HTML
python3 mail_archive.py pack         # сжать архив в файл
python3 mail_archive.py unpack       # развернуть файл обратно
python3 mail_archive.py delete       # удалить с сервера сохранённые письма
```

| Параметр | Назначение |
|---|---|
| `--dir ПУТЬ` | каталог архива, по умолчанию `./archive` |
| `--host СЕРВЕР` | IMAP-сервер |
| `--port ПОРТ` | порт (993 для SSL, 143 для STARTTLS) |
| `--user ЛОГИН` | логин |
| `--starttls` | STARTTLS вместо SSL |
| `--force` | для `render`: пересобрать все страницы заново |
| `--file ФАЙЛ` | для `pack` / `unpack`: файл архива, по умолчанию `<каталог>.tar.xz` рядом с каталогом |
| `--full` | для `pack`: сжать и HTML с вложениями, а не только оригиналы |
| `--level 0-9` | для `pack`: степень сжатия, по умолчанию 9 (максимальная) |

Примеры:

```bash
# архив на внешнем диске
python3 mail_archive.py --dir /Volumes/Backup/mail_archive

# пересобрать все HTML-страницы с нуля
python3 mail_archive.py render --force
```

Чтобы не вводить пароль вручную, его можно передать через переменную окружения `MAIL_PASSWORD`. Учтите, что так он может остаться в истории команд терминала.

Чтобы сменить сервер или логин, передайте `--host` / `--user` либо удалите `archive/config.json`.

## Структура архива

```
archive/
  index.html                  список папок — отсюда начинать просмотр
  config.json                 сервер, порт, логин (без пароля)
  INBOX/
    index.html                список писем папки
    eml/1234.eml              оригинал письма, точная копия с сервера
    html/1234.html            письмо для просмотра в браузере
    files/1234/отчёт.pdf      вложения этого письма
    folder.json               служебное: имя папки на сервере
    messages.json             служебное: размеры, даты и флаги писем
    index.json                служебное: кеш для списка писем
```

- Число в имени файла — номер письма на сервере (UID).
- Вложенные папки ящика записываются через точку: `INBOX.Работа`.
- **`.eml` — главное в архиве.** Это полные оригиналы писем; HTML и вложения в `files/` получены из них и в любой момент пересобираются командой `render`. Файл `.eml` открывается двойным щелчком в Почте, Thunderbird, Outlook.
- Файлы `*.part` — недописанные временные файлы после аварийного прерывания, их можно удалять.

## Просмотр архива

Откройте `archive/index.html` в браузере.

- **Список папок** → **список писем** (новые сверху) → **письмо**.
- В списке писем есть строка поиска. Она фильтрует по дате, отправителю, получателю и теме, но **не по тексту писем**.
- На странице письма: тема, от кого, кому, дата, ссылки на вложения и ссылка на оригинал `.eml`.
- Картинки, встроенные в письмо, показываются из локальных файлов. Картинки по внешним ссылкам (обычно в рассылках) грузятся из интернета и без сети не отобразятся.
- Скрипты из писем не выполняются.
- В `files/` кроме обычных вложений попадают встроенные картинки и дополнительные части письма (например, текст пересланного сообщения) под именами вида `part3.html`.

Поиск по тексту писем — средствами системы, например:

```bash
grep -rl "договор" archive/*/html
```

## Как безопасно освободить ящик

1. Запускайте скрипт, пока в итоговой таблице у всех нужных папок не будет ✓.
2. Соберите HTML и откройте `archive/index.html`. Выборочно проверьте несколько писем из разных папок, обязательно старые и с большими вложениями: вложения должны открываться.
3. Сделайте вторую копию каталога `archive` на внешний диск или в облако — после удаления писем с сервера этот архив станет единственным экземпляром:

   ```bash
   rsync -a archive/ /Volumes/Backup/mail_archive/
   ```

4. Только после этого удаляйте письма — командой `delete` (см. ниже), в веб-интерфейсе почты или в почтовом клиенте.
5. Если удаляли не скриптом, очистите корзину на сервере — квота освобождается только после этого.

После удаления писем `download` можно запускать и дальше: локальные копии удалённых писем останутся в архиве, новые письма будут добавляться.

## Превращение готовой копии в HTML: `render`

```bash
python3 mail_archive.py render             # архив в ./archive
python3 mail_archive.py render --dir ПУТЬ  # архив в другом каталоге
python3 mail_archive.py render --force     # пересобрать все страницы с нуля
```

Команда работает без сети и без пароля: берёт скачанные `.eml` и создаёт для каждого письма HTML-страницу, складывает вложения в `files/`, строит списки писем и папок.

- Повторный запуск обрабатывает только новые письма; уже готовые страницы не трогает.
- Прогресс, пауза и остановка работают так же, как при скачивании.
- Каталоги `html/` и `files/` и файлы `index.html` можно в любой момент удалить и собрать заново — оригиналы `.eml` при этом не меняются.

## Сжатие архива: `pack` и `unpack`

```bash
python3 mail_archive.py pack               # archive/ → archive.tar.xz
python3 mail_archive.py unpack             # archive.tar.xz → archive/
```

`pack` сжимает архив в один файл формата `.tar.xz` с максимальной степенью сжатия. Исходный каталог при этом **не удаляется** — если нужно освободить место, удалите его сами, когда убедитесь, что файл создан.

- **Что попадает в файл.** По умолчанию только оригиналы писем (`.eml`) и служебные файлы. HTML-страницы и вложения не сохраняются, потому что они полностью восстанавливаются из `.eml` командой `render`. Чтобы сжать всё как есть, добавьте `--full`.
- **Насколько сожмётся.** Зависит от содержимого. Текстовые письма сжимаются в разы. Ящик, где основной объём — фотографии, PDF и архивы во вложениях, уменьшится примерно на четверть.
- **Скорость.** Сильное сжатие медленное: на несколько гигабайт уходит час и больше. Быстрее, но слабее — `--level 6` или ниже.
- **Память.** При уровне 9 сжатию нужно около 700 МБ оперативной памяти.
- **Остановка.** Недописанный файл удаляется, сжатие придётся начинать заново.

`unpack` разворачивает файл обратно в каталог и, если в нём нет HTML-страниц, предлагает сразу их собрать.

```bash
# сжать в файл на внешнем диске
python3 mail_archive.py pack --file /Volumes/Backup/mail-2026.tar.xz

# развернуть его в другой каталог
python3 mail_archive.py unpack --file /Volumes/Backup/mail-2026.tar.xz --dir restored
```

Файл `.tar.xz` — стандартный формат: его откроет и обычный `tar -xf archive.tar.xz`, скрипт для этого не обязателен.

## Удаление писем с сервера: `delete`

```bash
python3 mail_archive.py delete             # архив в ./archive
python3 mail_archive.py delete --dir ПУТЬ  # архив в другом каталоге
```

**Удаление безвозвратное.** Письма стираются с сервера сразу, мимо корзины. Восстановить их можно будет только из локального архива.

Что делает скрипт:

1. Подключается к тому же ящику (сервер и логин берёт из `archive/config.json`, пароль спрашивает).
2. Сверяет каждую папку сервера с архивом и показывает таблицу:

   ```
     №  на сервере   удалить  останется  освободится  папка
     1        8425      8421          4       6.2 ГБ  INBOX
     2        1310      1310          0       2.9 ГБ  Отправленные
     3          57         0         57          0 Б  Спам  (нет локальной копии)
   ```

3. Спрашивает, в каких папках удалять (Enter — во всех, либо номера `1,3-5`).
4. Просит ввести слово `удалить`. Любой другой ответ — отмена, ничего не удаляется.
5. Удаляет пачками по 100 писем со строкой прогресса и в конце показывает, сколько писем было и сколько осталось в каждой папке.

Что важно знать:

- **Удаляются только письма, у которых есть локальная копия** — непустой файл `eml/<uid>.eml` в архиве. Всё остальное («останется» в таблице) скрипт не трогает: письма, пришедшие после последнего скачивания, и папки, которые вы не скачивали.
- Скрипт проверяет только наличие `.eml`. Открывается ли архив и есть ли у него вторая копия, проверьте сами заранее.
- Архив должен лежать распакованным каталогом: по файлу `.tar.xz` скрипт наличие копий не проверяет.
- Перед удалением стоит ещё раз запустить `python3 mail_archive.py`, чтобы докачать свежие письма.
- Пауза (`p`, пробел) и остановка (`q`, Ctrl+C) работают так же, срабатывают между пачками. Остановка не возвращает уже удалённые письма.
- Сами папки на сервере не удаляются, только письма в них.
- Если скрипт пишет, что письма в папке «будут только помечены удалёнными», очистите эту папку вручную в веб-интерфейсе или почтовом клиенте.

## Если что-то пошло не так

| Сообщение или симптом | Что делать |
|---|---|
| `Не удалось войти` | Проверьте логин и пароль. Возможно, доступ по IMAP нужно включить в настройках почты или требуется отдельный пароль для почтовых программ. |
| `Не удалось подключиться` | Проверьте имя сервера и порт. Попробуйте `--starttls --port 143`. Возможно, сервер доступен только из сети университета или через VPN. |
| `ошибка связи … переподключение` | Ничего, скрипт продолжит сам. |
| `Несколько ошибок подряд — похоже, нет связи` | Проверьте интернет и запустите скрипт снова. |
| `сервер его не отдал (удалено?)` | Письмо исчезло с сервера между сканированием и скачиванием. Запустите ещё раз — таблица сверки пересчитается. |
| `папка пропущена` | Сервер не дал открыть папку. Обычно это служебная папка без писем. |
| `у папки сменился UIDVALIDITY` | Сервер перенумеровал письма папки. Прежняя копия сохранена рядом в каталоге с суффиксом `.stale-…`, папка скачивается заново. |
| Клавиши `p` и `q` не работают | Скрипт запущен не в обычном терминале (например, с перенаправлением вывода). Останавливайте через Ctrl+C. |
| Письмо в браузере выглядит криво | Откройте оригинал по ссылке «Оригинал (.eml)» на странице письма. |
| `Не удалось обработать писем: N` при сборке HTML | Для этих писем нет HTML-страницы, но их `.eml` на месте и открываются почтовой программой. |
